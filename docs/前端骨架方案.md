# 前端骨架方案

本文档是 midea-cloud-control (美的美居桌面客户端) 渲染进程的工程骨架方案, 只覆盖工程结构, 不含业务与视觉设计.

## 1. 探测结论

| 项目       | 结论                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------ |
| 形态       | Electron 44 + electron-vite 6, renderer 为 React 19 + TypeScript 5.9 + Vite 8                          |
| 前端根     | `src/renderer/src` (依据: renderer 入口 `main.tsx` 在此)                                               |
| 别名       | `@renderer` -> `src/renderer/src` (`electron.vite.config.ts` 与 `tsconfig.web.json`)                   |
| off-limits | `src/main`, `src/preload`, 渲染进程只能经 preload 暴露的 `window.electron` / `window.api` 访问原生能力 |
| 既有约定   | ESLint flat config (electron-toolkit + react/hooks/refresh), Prettier (单引号, 无分号, 100 列)         |
| 包管理器   | npm, 开发命令 `npm run dev`                                                                            |

## 2. 第一阶段范围

第一阶段只搭工程骨架本身: 目录与模块边界, token 结构, 主题机制, i18n, 无障碍基线, enforcement, 以及让管道跑通所需的极少量基础组件. **不含任何业务页面, 业务功能或 feature 空壳.**

## 3. 工程选型

| 维度       | 选型                                               | 理由                                                            |
| ---------- | -------------------------------------------------- | --------------------------------------------------------------- |
| 样式       | Tailwind CSS v4 (CSS-first, `@tailwindcss/vite`)   | 原子类与 CSS 变量 token 同源, 便于 lint 拦截任意值逃逸          |
| UI 组件    | shadcn/ui (源码型, 基于 Radix)                     | 组件源码可控, 无障碍行为内建, 与 Tailwind 和 token 契合         |
| i18n       | react-i18next + ICU 消息格式                       | React 生态主流, ICU 统一处理复数, 数字, 日期                    |
| 主题       | CSS 变量 + `.dark` class, 默认跟随系统, 可手动切换 | 与 shadcn/ui 的暗色约定一致, 明暗只换语义 token 指向            |
| 路由       | react-router, hash 模式                            | Electron 生产环境以 `file://` 加载页面, hash 路由无需服务端回退 |
| 全局状态   | 不引状态库, 用 React Context + hooks               | YAGNI, 出现跨模块复杂共享时再评估                               |
| 组件工作台 | 不引 Storybook                                     | 靠目录约定与软约束落实 "组件先于页面"                           |

具体安装与配置方式以实施时 Context7 查到的各库当前官方文档为准.

## 4. 目录规划

全部位于前端根 `src/renderer/src` 下, 以 `@renderer/*` 别名引用:

```text
src/renderer/src/
  app/              # 应用装配: 根组件, provider, 路由, 全局布局
  features/         # 按业务领域切分, 每个领域自包含 (第一阶段为空)
  components/
    ui/             # shadcn/ui 生成的基础组件 (库封装层)
  hooks/            # 跨领域通用 hooks
  lib/              # 第三方封装与适配层 (如 cn 工具, i18n 初始化)
  styles/           # 设计 token 与主题
  locales/          # i18n 文案资源
  types/            # 跨领域通用类型
```

依赖方向 (由 lint 硬卡): `app` -> `features` -> shared (`components`, `hooks`, `lib`, `types`, `styles`, `locales`), 反向禁止, feature 之间禁止直接互相引用, 前端根内禁止引用 `src/main` 与 `src/preload`.

## 5. 设计 token 结构

三层 token 落为 CSS 变量, 分文件存放于 `styles/`:

| 文件                    | 层级           | 内容                                                                                |
| ----------------------- | -------------- | ----------------------------------------------------------------------------------- |
| `tokens.primitives.css` | 第 1 层 原始值 | 唯一允许出现颜色字面量与原始尺寸的文件                                              |
| `tokens.semantic.css`   | 第 2 层 语义   | shadcn/ui 约定的语义变量 (`--background`, `--primary` 等), 全部引用原始值, 明暗两套 |
| `tokens.components.css` | 第 3 层 组件   | 组件级特例, 按需添加                                                                |
| `theme.css`             | 汇总           | 引入 Tailwind 与各层 token, 用 `@theme inline` 把语义变量映射为 Tailwind 工具类     |

铁律: 组件与页面只引用语义层与组件层, 禁止引用原始值层或硬编码颜色与尺寸. 骨架期先填一套中性占位值, 真实值由设计阶段填入.

`theme.css` 用 `--color-*: initial` 清空了 Tailwind 默认调色板, 颜色工具类只能来自语义 token.

shadcn/ui 配置见项目根 `components.json`; CLI 通过根 `tsconfig.json` 的 `paths` 解析 `@renderer/*`, `tsconfig.web.json` 继承根配置, 别名只定义一处 (另有 `electron.vite.config.ts` 的运行时别名).

## 6. 主题机制

- 主题偏好分三种: 跟随系统, 亮色, 暗色; 默认跟随系统, 偏好保存在 `localStorage`.
- 生效方式: 在 `<html>` 上切换 `.dark` class, 语义 token 在 `.dark` 下换指向, 组件不感知主题.
- 由 `app` 层的主题 provider 统一管理, 系统主题变化时实时响应.

## 7. i18n 机制

- 文案一律经 react-i18next 的 `t()` 获取, 禁止在组件中硬编码可见文案.
- 消息格式采用 ICU, 复数, 数字, 日期等变体收在文案资源中.
- 语言: 先铺 `zh-CN`; 另设仅开发环境可用的伪本地化语言, 用于暴露漏翻文案与文本膨胀导致的布局问题.
- 布局一律使用 CSS 逻辑属性 (Tailwind 的 `ms-*`, `pe-*`, `text-start` 等), 为 RTL 预留.

## 8. 无障碍基线

- 正文与背景对比度满足 WCAG AA (正文 >= 4.5:1, 大字 >= 3:1), 明暗两套都要满足; 由设计阶段填值时校验.
- 所有交互元素键盘可达, 焦点样式可见且取自 token.
- 优先使用语义化标签与 shadcn/ui 组件内建的 ARIA 行为; `eslint-plugin-jsx-a11y` 做静态兜底.

## 9. Enforcement 计划

| 机制               | 内容                                                                                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| manifest           | `.claude/frontend-skeleton.json` 记录前端根, 别名, zone, off-limits, 选型与 token 文件, 作为单一事实源                                                        |
| ESLint (硬约束)    | 禁裸原生交互元素 (`components/ui` 除外); 禁引用原始值层; 禁引用 off-limits; 单向依赖与 feature 隔离; 禁 Tailwind 任意值与未注册类名; 强制逻辑属性类; jsx-a11y |
| Claude Hooks       | PreToolUse 注入软约束清单; PostToolUse 对改动的前端文件运行 ESLint 并回灌结果                                                                                 |
| CLAUDE.md (软约束) | 相似 UI 出现 2 次以上必须抽象; 优先用库组件, 禁手搓等价复合控件; 组件先于页面                                                                                 |

## 10. 验收标准

- `npm run lint`, `npm run typecheck`, `npm run build` 全部通过.
- 在 `npm run dev` 启动的真实应用中, 用临时展示页验证: 语义 token 生效, 主题可在跟随系统, 亮色, 暗色间切换, 语言可在 `zh-CN` 与伪本地化间切换, shadcn/ui 组件正常渲染且键盘可操作.
- 验收后删除临时展示页, 保留全部工程成果.
- enforcement 装好后, 故意写一处违规 (如裸 `<button>`) 能被 lint 拦下.

## 11. 视觉方案

由 frontend-router 的设计阶段填写, 本骨架不做任何视觉决策.

设计 brief: 美的美居的桌面客户端, 用于在电脑上通过云端查看和控制美的智能家居设备. 气质要现代, 清爽, 可信, 亲和; 信息密度中等, 设备状态一目了然, 操作反馈明确.

待设计阶段决定的事项:

- 视觉方向与品牌调性.
- 配色体系的具体值 (主色, 中性阶, 语义色, 明暗两套).
- 字体, 字号层级与行高.
- 风格基调.
- 三层 token 的具体值与组件规格.
- 组件与页面的视觉实现.
